# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Cargo workspace of 9 Substreams packages (`polymarket-*`) that extract Polymarket
events on Polygon, plus `polymarket-substreams-common` — a plain shared helper crate
(no wasm target, no manifest). All 9 packages are released in lockstep at the same version.
`polymarket-trades` builds on the sibling `polymarket-exchange`, `polymarket-neg-risk-ctf`
and `polymarket-resolution` manifests' map outputs (it imports them, so build those first:
`make build-trades` does). Its only block-reading module is `map_orders`, which decodes
exchange settlement calldata (`polymarket_substreams_common::orders`). Its `db_out`
(PostgreSQL, `schema.sql`) and `db_out_clickhouse` (`clickhouse-schema.sql`) feed
`substreams sink postgres|clickhouse`; delta upserts (`add`/`max`/`min`/`set_if_null`)
are PostgreSQL-only, so the ClickHouse module inserts fragments for the table engines to merge.

## Build / test / lint

- Build one package: `cd polymarket-<name> && substreams build` (runs `buf generate` then a cargo wasm release build).
- Build all: `make build-all`.
- Test: `cargo test` at the repo root. Tests are expensive, so CI runs them **only on release** (`v*` tag push) — run them locally before pushing.
- Lint: `cargo clippy --workspace --all-targets -- -D warnings` (also run by the pre-commit hook).
- CI is split in two:
  - `.github/workflows/ci.yml` — on every push/PR, runs **clippy only**.
  - `.github/workflows/release.yml` — **only on `v*` tag push**: runs `cargo test --workspace`, and only if it passes builds, creates the GitHub Release and publishes. Don't add `cargo test` back to `ci.yml`.

## Generated code — do not hand-edit

`src/pb/` is generated by `buf generate` (per-package `buf.gen.yaml`); `src/abi/` is
generated by `build.rs` from `abi/*.json`. Both are committed to git but are
regenerated by `substreams build`. Edit the `.proto` schema or the ABI JSON — never
the generated `.rs` files. `cargo fmt` follows `mod abi;` into the generated files and
reformats them; revert those (or run `rustfmt` on the hand-written files only).

## Substreams conventions (match the existing packages)

Reference: [streamingfast/substreams-skills](https://github.com/streamingfast/substreams-skills)
`develop` (mainly `substreams-dev`, `substreams-ethereum`, `substreams-testing`). Last
audited against commit `8959b1a`; check upstream `develop` against that commit before
changing these rules.

- Handlers take a **lazy block view**: `fn map_x(blk: &eth::BlockLazyView<'_>)`. The
  signature alone selects lazy decoding (no manifest change), so only the fields read
  get decoded.
- Every `#[substreams::handlers::map]` fn calls `substreams::skip_empty_output();` as its
  first statement, so empty outputs aren't emitted or cached and downstream modules skip.
- Reach logs through `polymarket_substreams_common::block_logs(blk, is_x_contract)?`, then
  `for log in &blk.logs { … }`. It walks successful transactions' receipt logs once, keeps
  only those whose emitting address passes the predicate, and pairs each with its tx hash.
  Don't use the upstream `blk.logs()` / `transactions()` lazy iterators in handlers: they
  `expect()` on malformed data inside the crate, while `block_logs` returns those decode
  errors with `?`.
- Contract predicates compare 20-byte constants directly:
  `const X: [u8;20] = hex_literal::hex!("…"); fn is_x(address: &[u8]) -> bool { address == X }`.
  Never compare addresses as hex strings (~25× slower).
- `map_all_events` does a **single pass** over the kept logs, classifying each log via an
  if/else-if chain into category structs.
- The per-category modules (`map_fee_events`, `map_ctf_events`, `map_oracle_events`, …) stay
  alongside `map_all_events` / `map_resolution_events` by Colin's decision (SUB-4, 2026-11-03),
  even though substreams-dev prefers one extraction module per block. They are public API:
  don't deprecate or remove them, and keep them in step with the combined module.
- **No `.unwrap()` / `.expect()` / `panic!` in handlers.** Decode with
  `if let Ok(ev) = Event::decode(&log.log)` and skip on error. (`.expect()` is fine inside
  `#[cfg(test)]`, benches and examples.)
- Use the shared helpers from `polymarket-substreams-common` (`block_logs`, `tx_context`,
  `bigint_to_string`, `bigint_to_u32`, `format_address`); don't re-implement them per package.
- Every event proto carries `tx: Option<TransactionContext>`, populated via the package's
  `build_transaction_context(&blk, log)` wrapper around `tx_context`.
- Lazy handlers make the macro's generated shim trip `clippy::not_unsafe_ptr_arg_deref`;
  each package allows it at crate scope (see the comment at the top of each `lib.rs`).
- Tests: fixtures are owned `eth::Block`s. Run a handler with
  `with_lazy_block(&block, |blk| substreams::testing::map!(map_x(blk)))`, which encodes the
  block and decodes it lazily the way the runtime does. Never call `__impl_map_x` directly.
- Real-block fixtures are shared at the repo root, `testdata/polygon_<block>.binpb.b64`
  (96600000 has events for every package but resolution, which uses 96591795). Capture one
  with `scripts/capture_fixture.sh <block>`; load it with
  `polymarket_substreams_common::load_block_b64` (the `fixtures` feature, enabled from each
  package's `[dev-dependencies]` only, so base64 never reaches the wasm build). Each package's
  `fixture_tests` asserts the same counts as its `tests/assertions.yaml`, which may
  cover several modules (the runner makes one run per module and block).
- `scripts/run_test_files.sh` runs every `tests/assertions.yaml` against the chain (needs
  `make build-all`, `substreams auth`, jq); run it before each release. It checks the
  assertions itself with jq because `substreams run --test-file` (v1.26) never fails a run
  and reports only in the TUI.

## Performance checks

- `cargo bench -p polymarket-substreams-common --bench lazy_vs_owned`: native Criterion
  bench of the extraction step, owned `Block` vs lazy view.
- `scripts/wasm_bench.js`: times a handler inside the built WASM and hashes its output, so
  builds can be compared for speed and byte-identical results (usage in the file header).
  The release profile's `opt-level = 's'` was chosen with it (SUB-6).

## trader-index: the warm index

`polymarket-trader-index/substreams.yaml` imports the **published v1.0.0** of itself as
`warm` and takes `map_user_keys` and `index_users` from it with `use:`. This isn't
circular: `warm` is the frozen registry release, not this manifest. Any crate change
re-hashes those two modules, and a new `index_users` hash means re-warming the index from
block 4023686 (`map_user_activity` returns nothing until then). Keep them on `warm` until
a release deliberately accepts that re-warm. The Rust handlers for both are kept current
but unused by the manifest until then.

## Running against the chain

Needs `substreams auth` first (API key from thegraph.market). Endpoint: `polygon.streamingfast.io:443`.

## Releases

Versions bump across ALL 9 manifests (`package.version`, plus
`polymarket-trades/substreams.clickhouse.yaml`) and the versioned `.spkg`
references in the READMEs in lockstep, in one commit. Then push tag `vX.Y.Z`. The tag push
runs `release.yml`: workspace tests, then build, GitHub Release and publish. To publish
by hand, use `./publish-all.sh` (needs `substreams auth` / a substreams.dev token).
